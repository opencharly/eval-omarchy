## Findings

1. **cardwire is not in the omarchy package repo (dependency gap).**
   `omarchy-pkg-add cardwire` (the toggle's install path) resolves via pacman;
   omacom/omarchy-pkgs ships `pkgbuilds/supergfxctl` but no `cardwire`. The
   PR's own note admits "the omarchy package repo needs to ship cardwire in
   place of the retired supergfxctl". Until that lands, the toggle's install
   path fails on a real system and the L3 full-switch-cycle bed cannot complete.
2. **L3 hybrid bed: PARTIAL/NOT-EVALUABLE (hardware-bound, never faked).** The
   host is passthrough-ready (NVIDIA 10de:2702 bound to vfio-pci, IOMMU on), so
   check-omarchy-hybrid-gpu-vm is feasible in principle; but the full switch
   cycle (bind/unbind, PCI runtime PM, compositor restart) requires cardwire
   installed in the guest, which is blocked by finding 1. The script-level
   behavior is fully proven by this Tier-1 run; the hardware cycle is deferred
   until the package repo ships cardwire.
3. **Retired-file cleanup is unconditional.** The toggle removes
   `/etc/supergfxd.conf`, the force-igpu hook and the delay-start drop-in
   whenever supergfxd is present — including on a system that never used the
   supergfxd workarounds. Harmless (the files are absent), but the PR's own
   test asserts the same unconditional behavior, so this matches intent.
