# 2026.256.2224 — feat(eval): track the lane results + a large-file gitignore safety net

## Summary

A **config-only** change, 4 files (`.gitignore`, `charly.yml`, and the two tracked reports carrying the stale footer), no runtime path.

**1. `.gitignore` — a large-file TYPE-level safety net.** The existing rules ignore the `media/` and `output/` DIRECTORIES, which covers every disk image and recording the lane produces — but a stray large file elsewhere would still be committable. Added disk-image (`*.qcow2 *.qcow *.iso *.raw *.img *.vmdk *.vdi`), recording (`*.mp4 *.mjpeg *.m4v *.mov *.webm *.mkv *.avi *.gif *.cast`) and screenshot (`*.png *.jpg *.jpeg`) patterns.

**2. `charly.yml` — the report-template footers no longer overclaim.** Both templates hardcoded `(fully tested and validated)` on EVERY report. The emitted strings are now:

| Template | Renders when | New footer | Why truthful |
|---|---|---|---|
| main report | `@eval.verdict` is PASS/FAIL only (render-report `skip_when`) | `(analysed on a live system)` | a live eval bed ALWAYS ran for this class; never a full validation |
| not-testable | `@triage.class == skip` | **no tier** — `(triage only — no validation performed)` | triage-only, no bed; the triaged PR is typically a WIP **code** diff, so documentation-reviewed is illegal and live-system is false |

**Maintainer sign-off requested (finding 1).** For the `skip` class **no rulebook attribution tier is truthful**: it runs no bed, and its PR is usually a WIP code diff — so `documentation reviewed` (docs-only) and `analysed on a live system` (a run happened) are both false. Rather than assert a false tier class-wide, the skip template carries a plain disclosure plus the already-honest `*Tested-by: … (triage only; no bed run)*`. Requesting explicit maintainer sign-off for a disclosure instead of a tier on triage-only records.

**3. R5 sweep of the stale footer.** The old string `(fully tested and validated)` survived in the two TRACKED reports `eval/pr-10115.md` (class visual) and `eval/pr-11072.md` (class skip); both are corrected in this commit (`eval/pr-10115.md` → `analysed on a live system`; `eval/pr-11072.md` → the triage disclosure).

**Scope note (NOT in this PR): the run's generated results.** The live 16-lane, 32-PR run's outputs (blank `metrics/*.md` from a failed `ledger-gate`, an empty acceptance matrix, reports recording zero executed checks) are **invalid failure records** and are deliberately not landed as "results"; they remain on disk and will be committed by the named thematic batch **`feat/live-lane-eval-batch`** once `plugin-pipeline#21` + the channel-timeout/shell-readiness follow-ups land (B6/R2).
