## Summary

Recreate all 8 omarchy PR eval configs from scratch per the new eval guidelines, and land the supporting guidance. This is the follow-up to the merged docs rework (PR #8).

**Full RCA (recorded in plan/pr-eval-user-voice-rework.md):** the initial pod-tier checks substituted mocked external tools (cardwire/supergfxd, df/findmnt, flatpak profile) and the reports claimed live behavior from them — a collapse of the eval guidance. Root cause: the contract was never operationalized into enforceable rules.

**The eval rules (now standing rules in `eval/PR-EVAL-LANE.md`):**
1. **NEVER mock anything — ever** (first and foremost): a mocked check is not evidence; a report built on mocks is useless
2. Test like a user, not a validator
3. Assisted-by footer on every posted comment
4. Install missing software in the test environment and re-run before "couldn't be tested"
5. Test to the maximum extent possible — on a live system (system-behavior PRs MUST be tested on a live omarchy VM, never only in a container)
6. Record every evaluation — both lanes, saved to the gitignored `media/`
7. Create reusable software packages when software is missing
8. Triage before authoring a validation (usefulness, new insight, hardware testability, tier routing)
9. Every PR-specific check must fail without the PR (the known-red fixture)
- "What each tier proves (honest semantics)": a container run proves script logic and file application with REAL tools, never live system behavior; system-behavior claims come from the Tier-2 live VM
