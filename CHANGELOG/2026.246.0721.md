# 2026.246.0721 — docs(eval): binary verdict semantics — PASS/FAIL/NO VALIDATION, no 'might work' framings

## Summary

The validation's purpose is binary: **does it actually work?** The only valid verdicts are PASS (verified working on a live system) and FAIL (verified not working on a live system). NO VALIDATION means the validation itself failed — it could not answer the question because the core behavior could not be tested on a live system.

**Strict prohibition:** any "might work" / "mostly works" / "it works" evaluation NOT verified on a live system is **strictly forbidden** — it fakes success for something the validation could not test. A pod-only eval is NOT a validation: the container tier cannot test live system behavior, so a container run of a system-behavior PR proves nothing about the PR and must never be presented as a validation. If the validation cannot test the thing on a live system, the validation itself FAILS — the result is NO VALIDATION, and no report is produced.

**This change (multi-level, per the RCA in plan/pr-eval-user-voice-rework.md):**
- Lane doc: binary verdict semantics + strict prohibition (replaces the earlier hard-fail/no-validation framing)
- Template: PASS / FAIL / NO VALIDATION verdict options; "it works"/"mostly works"/"might work" for unverified behavior strictly forbidden
- AGENTS.md: binary verdict semantics + strict prohibition
- README: binary verdict semantics note
- **All 8 reports: verdicts are NO VALIDATION** — the pod-only evals could not test the live behavior, so the validation itself failed; no report claims the PR works
