# 2026.259.1014 — feat(eval): schema-first record emission + org pr-validator grading

## Summary

Reworks the omarchy PR-eval lane on two axes.

**1. Grade the PR by the ORG pr-validator criteria, with the lane running the R10.** The lane evaluates an `omacom/omarchy` PR on a disposable golden-VM clone. A new `validate` agent stage grades it against the org-wide `pr-validator` spec, scoped to an upstream PR by an **applicability map** in the entry `omarchy-eval` skill. The one substitution: the pr-validator normally ASSUMES the author ran R10 and pasted the evidence; this lane RUNS the R10 itself (oracle-planned, control-proven, live VM) and the grader consumes THAT ledger — the PR body is a claim under test, never evidence.

**2. charly WRITES the record — no hand-written or string-templated YAML.** The `record`/`not-testable` stages are now `kind: emit` with `schema: candy/eval-pr/record.cue#EvalRecord` / `...#NotTestableRecord`. The structured value is validated against the CUE schema with Concreteness required BEFORE any bytes are written, then marshalled by the CUE YAML encoder. A colon in an unquoted scalar can no longer produce an unreadable record (RCA 2026.259 — the old free-form `generate` template emitted `what: Docs-only change: …`, so the oracle's render-once cache crashed on the NEXT run). Every level of the schema is `close(...)`d — the two record defs, every nested struct, AND the `#EvalCheck`/`#EvalStep` list ELEMENT defs. Adding a record field means editing `record.cue` first.

The `charly-writes-the-YAML` rule is stated in `AGENTS.md` and the entry skill.

Docs updated: `README.md`, `AGENTS.md`, `CONTRIBUTING.md`, `VISION.md`.

**Dependency resolved.** The `kind: emit` stage ships in [opencharly/plugin-pipeline#25](https://github.com/opencharly/plugin-pipeline/pull/25) — **merged and tagged `v2026.259.0809`**. This PR bumps the pin and runs on it.
