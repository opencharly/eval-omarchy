# 2026.250.1750 — feat(eval): work-lane frontmatter schema + routing table

## Summary

Adds the work-lane schema to the eval lane contract (plan PR6): **eval/references/work-lane-schema.md** defines the structured frontmatter every NEW eval report (eval/pr-<N>.md) carries — `eval: {pr, title, head_sha, triage, class, channel, tier, known_red, cold_read, verdict, hardware_bound, posted}` — plus the routing table (which field combinations gate what: known_red broken → PROCESS BLOCK; verdict NO_VALIDATION → no report; cold_read fail → fix not post; stale head → regenerate; pod-tier for a system-behavior class → HARD FAIL; posted stays false until an operator posts). Existing reports are **grandfathered** — the schema governs new evals only.

Adapted from ClawSweeper's work-lane structure (no close/merge lanes — an eval never closes or merges anything). Single source: the schema is defined here once; the cold-reader rubric and template reference it.
