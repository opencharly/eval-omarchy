# 2026.246.0539 — docs(eval): rework PR-eval template + lane to a user-testing voice

## Summary

Rework the omarchy PR-eval template and lane guidelines so reports and posted PR
comments read like **another user who actually tried the PR** instead of a strict
validation tester — first person, behavior-focused, honest about what worked and what
did not — while keeping the full evidence rigor (step matrix, per-check matrix,
findings tied to evidence). All terminology is plain language, understandable to an
average user and to an agent that knows nothing about opencharly.

**`eval/PR-EVAL-TEMPLATE.md`** — user-testing voice:
- `## Verdict` → `## How it went` ("it works / mostly works / I couldn't fully test it" + first-person `What I did`)
- `## Evidence` → `## What I ran` · `## Findings` → `## What I noticed` · `## Eval checklist` → `## What I checked` · `## Provenance` → `## Who ran this`
- EXTERNAL, NON-AUTHORITATIVE disclaimer kept verbatim; human-approval-before-posting and the result cache kept
- Recordings section is now MANDATORY (both lanes: asciinema terminal + full-screen video), artifacts saved to the gitignored `media/<pr>-<calver>/`
- Render instructions mandate the `*Assisted-by: …*` footer on every posted comment

**`eval/PR-EVAL-LANE.md`** — new "Standing rules (every PR evaluation)" section:
1. Test like a user, not a validator
2. Assisted-by footer on every posted comment
3. Install missing software in the test environment and re-run before "couldn't be tested" (canonical case: pr-9332's cardwire gap)
4. Test every PR to the maximum extent possible (all test environments, edge cases, the PR's own Verification claims)
5. Record every evaluation in BOTH lanes, saved to the gitignored `media/`
6. Create reusable software packages (`omarchy-pr-apply`, `omarchy-eval-record`, `cardwire`) following the established authoring rules
7. **Triage before authoring a validation** — is the PR useful, would the evaluation add new insight, and can the core behavior be tested on the available hardware? PRs that fail triage get a short triage note, not a report
- Mechanics sharpened: the apply seam is a local software template nested under the VM test environment, applied to the per-channel clean snapshot VM; prove it on a real VM before claiming the lane

**`.gitignore`** — gains `media/` (recording artifacts are large binaries; small evidence stays committed in `eval/evidence/`). This line is a documentation-support change: it materializes the `media/` directory the docs mandate for recordings.

**`README.md`** — layout table gains `eval/PR-EVAL-LANE.md`, `eval/evidence/`, and `media/` rows; user-testing voice + triage gate noted; one-line "what is charly / what is a candy" explanation added.
